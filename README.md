# 待办清单

一个在 Windows 上离线使用的个人待办清单。首页的“现在先做”显示当前排在第一位的任务、它离截止还有多久，以及综合得分。

## 第一次打开

双击 `dist\TodoList.exe` 即可使用，也可以把这个 exe 单独复制到其他文件夹。程序已内置 Python 运行环境。首次打开时，点“添加第一件任务”，输入名称，选择重要程度，然后保存。

截止时间可以留空、手写，也可以点“选日期”从日历中选择。手写支持 `2026-11-23 18:30` 和中文冒号写法 `2026-11-23 18：30`。只填日期时，截止时间默认是当天 23:59。用日历更改日期会保留已经填写的时分，选好后也可以继续手动修改。

完成推荐的任务后，点推荐卡上的“标记完成”，下一项会立即出现。在列表里选中一项，可以编辑、完成或删除。误点完成时，到“已完成”列表选中任务并点“恢复待办”。

数据自动保存在当前 Windows 用户的数据库中。在资源管理器地址栏输入 `%LOCALAPPDATA%\TodoList` 即可找到 `tasks.db`。要把清单带到另一台电脑，先关闭程序，备份这个数据库，再把它放入新电脑上同一用户目录位置。

## 推荐顺序

重要程度由你选择，紧迫程度由截止时间自动计算。

| 分值 | 重要程度 | 紧迫程度 |
| --- | --- | --- |
| 2 | 重要 | 迫切，已到期或剩余时间 ≤ 24 小时 |
| 1 | 一般（默认） | 一般，24 小时 < 剩余时间 ≤ 72 小时 |
| 0 | 水水就行 | 轻松，剩余时间 > 72 小时，或未设截止时间 |

清单按两项分值之和从高到低排列。总分相同时，按“重要、一般、水水就行”的顺序推荐。重要程度也相同时，截止较早的优先，无截止时间的排在这一组末尾。条件完全相同时，先添加的排在前面。逾期任务会显示超时时长，继续按同一规则参与排序。窗口每分钟重新计算紧迫分并排序，打开或切回窗口时也会刷新。

例如，明天要参加的座谈会标为“水水就行”，距离截止还有 5 天的开题报告标为“重要”，两项都得 2 分，优先推荐开题报告。当报告距截止还有 72 小时时，它自动升到 3 分；剩余 24 小时时升到 4 分。

## 键盘操作

| 操作位置 | 按键 | 功能 |
| --- | --- | --- |
| 主窗口 | Ctrl + N | 添加任务 |
| 主窗口 | Ctrl + Tab | 切换待办与已完成 |
| 任务列表 | ↑ / ↓ | 选择任务 |
| 任务列表 | Enter | 编辑选中任务 |
| 任务列表 | 空格 | 完成或恢复选中任务 |
| 任务列表 | Delete | 打开删除确认框 |
| 添加或编辑窗口 | Enter / Esc | 保存或取消 |

## 从源码运行和打包

开发环境为 Windows 64 位、Python 3.12。以下命令在项目目录的 PowerShell 中运行。源码运行使用 Python 自带的 Tkinter 和 SQLite。

```powershell
py -3.12 main.py
```

运行自动测试，覆盖推荐规则和数据库读写。

```powershell
py -3.12 -m unittest discover -s tests -v
```

首次打包时创建虚拟环境并安装打包工具。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
```

关闭正在运行的目标 exe，再执行下方命令。生成的文件为 `dist\TodoList.exe`。

```powershell
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --onefile --windowed --name TodoList --icon todo.ico --add-data "todo.ico:." main.py
```

## 从哪里开始读代码

| 想了解或修改什么 | 从这里开始 |
| --- | --- |
| 时间分档、总分、同分顺序 | `model.py` 中的 `urgency`、`score` 和 `rank_tasks`。24 小时和 72 小时对应文件顶部的两个常量。 |
| 窗口、表单、推荐理由 | `ui.py` 中的 `TodoApp` 和 `TaskDialog`。 |
| 任务如何写入文件和恢复 | `storage.py` 中的 `TaskStore`。 |
| 程序从哪里启动 | `main.py` 打开数据库并创建主窗口。 |

Git 记录了排序规则、桌面界面和测试打包三个开发阶段。用 `git log --oneline` 查看历史，用 `git status` 查看本地修改。改完排序规则后，可以先运行测试，再用 `git diff` 检查改动并提交。数据库、虚拟环境和打包产物由 `.gitignore` 排除。
